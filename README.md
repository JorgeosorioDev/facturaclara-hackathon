# FacturaClara

Invoice and receipt scanner for small businesses in Colombia.
Upload a photo, get validated accounting data checked against Colombian tax rules, and query your expenses with an assistant that never invents numbers.

Built for the **Meta Global AI Developer Hackathon** (Indie Developer track, *Build for Your World* theme).
Author: Jorge Osorio · October–November 2026.

> **New work only:** all code in this repository was written between October 26 and November 4, 2026. It contains no code from earlier projects.

---

## Problem

Small businesses in Colombia type invoices and receipts by hand into spreadsheets. That takes hours, introduces errors in tax IDs (NIT), VAT (IVA), and totals, and leaves expenses invisible until month end. A generic OCR extracts text, but it doesn't know that a NIT has a check digit or that VAT must add up to the total.

## Solution

1. The user uploads a photo of an invoice from the browser or phone.
2. **SAM 3.1** segments the document and crops the paper from the background.
3. **Muse Spark** extracts a JSON object with a fixed schema: supplier, NIT, date, line items, subtotal, VAT, total, and suggested category.
4. **Deterministic validation** (our own code, no AI): NIT check digit, sum of items + VAT ≈ total, required fields. Each failure shows a message in Spanish.
5. The user corrects fields if needed and saves the invoice to PostgreSQL.
6. The **assistant** classifies the question (with Muse Spark) and answers with figures computed in SQL, never generated by the model.

## Quick demo

```
Invoice photo → extracted data → alert "The VAT doesn't match the total"
→ manual correction → save → "How much did I spend on transport in October?" → real figure from SQL
```

## Architecture

```
Browser / phone (Next.js)
  │  POST /scan (photo)
  ▼
FastAPI
  ├─ SAM 3.1 ............ mask + document crop
  ├─ Perspective correction (OpenCV)
  ├─ Muse Spark ......... extraction → JSON (schema below)
  ├─ DIAN validator ..... NIT, sum, required fields (deterministic)
  ├─ PostgreSQL 16 ...... invoices, items, categories
  └─ Assistant .......... intent (Muse Spark) → fixed SQL → answer
```

## Extraction JSON contract

```json
{
  "proveedor": "string",
  "nit": "string",
  "fecha": "YYYY-MM-DD",
  "items": [{ "descripcion": "string", "cantidad": 1, "precio_unitario": 0, "total": 0 }],
  "subtotal": 0,
  "iva": 0,
  "total": 0,
  "categoria_sugerida": "papeleria | transporte | servicios | alimentacion | salud | otros",
  "confianza": 0.0
}
```

Field names are kept in Spanish to match the Colombian invoice domain. Currency is COP, integers without separators. If a field can't be read, it is `null`; it is never invented.

## Validation rules

| # | Rule | On failure |
|---|---|---|
| 1 | NIT has 9–10 digits and a valid DIAN check digit | "NIT no reconocido, revísalo" |
| 2 | `sum(items.total) + iva` ≈ `total` (tolerance $100 COP) | "Los valores no cuadran" |
| 3 | `proveedor`, `fecha`, and `total` are required | "Falta {campo}" |

**Check digit:** weights `3, 7, 13, 17, 19, 23, 29, 37, 41, 43, 47, 53, 59, 67, 71` applied right to left over the NIT digits; `r = sum % 11`; if `r > 1` then `DV = 11 − r`, otherwise `DV = r`.

## Assistant: closed intents

| Intent | Example | Query |
|---|---|---|
| `total_mes` | How much did I spend in October? | `SUM(total)` grouped by month |
| `total_categoria` | How much did I spend on transport? | `SUM(total)` by category |
| `total_proveedor` | How much have I bought from X? | `SUM(total)` by supplier |
| `ultimas_facturas` | Show me the latest ones | last 5 rows |

If the question doesn't match: *"I can tell you totals by month, category, or supplier."*

## Setup

1. Copy `.env.example` to `.env` and fill in:

```bash
META_API_KEY=...          # Meta Model API
BASETEN_API_KEY=...       # optional: Baseten, only for Muse Spark Open
DATABASE_URL=postgresql://facturas:facturas@db:5432/facturas
CACHE_DIR=./cache         # model responses saved by image hash
MAX_DAILY_CALLS=60        # daily call cap (budget control)
```

2. Start everything:

```bash
docker compose up --build
```

- API: http://localhost:18001 · `GET /health`
- Frontend: http://localhost:3000

> `.env` is never committed. Check with `git status` before every push.

## Usage

```bash
# Extract one invoice from the command line
curl -F "file=@fixtures/factura_01.jpg" http://localhost:18001/scan

# Measure per-field accuracy over the fixtures
python scripts/eval_extraction.py --fixtures fixtures/ --report reports/precision.md
```

## Extraction accuracy

Measured on 3 fixtures with real runs (2026-10-29, all `cache_hit=False`), set ampliable. Full per-field detail in `reports/precision.md`.

| Fixture | Supplier | NIT | Date | VAT | Total | Hits |
|---|---|---|---|---|---|---|
| Factura-FV-2-4.pdf | ✓ VEFLAT SAS | ✓ 901475872-2 | ✓ 2026-10-16 | ✓ null (no VAT line) | ✓ 4033.57 | 5/5 |
| factura_mesa.jpg | ✓* intentionally anonymized (model returned the real one) | ✓ 900055719-8 | ✓ 2026-09-01 | ✓ null (no VAT line) | ✓ 413580 | 5/5* |
| invoice.png | ✓ VEFLAT SAS | ✓ 901475872-2 | ✓ 2026-10-16 | ✓ null (no VAT line) | ✗ model rounded 4033.57 → 4033 | 4/5 |
| **Total** | | | | | | **14/15 ≈ 93%** |

Note: the only REAL model error is the `invoice.png` total (rounding 4033.57 → 4033). `*` = supplier intentionally anonymized in the expected file (privacy), counted as known-non-error.

## Scope and limits

**Included:** photo upload, segmentation, extraction, validation, manual editing, saving, categories, assistant queries, CSV export.

**Out of scope (next steps):** multi-user authentication, integration with DIAN electronic invoicing (XML/UBL), handwritten invoices, multi-currency, native mobile app.
